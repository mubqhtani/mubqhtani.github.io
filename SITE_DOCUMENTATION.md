## 4. Configuration

### `next.config.ts`
- `output: "export"` → `npm run build` writes a static site to `out/`.
- `basePath` = `process.env.BASE_PATH ?? ""`. Empty for `mubqhtani.github.io` (a user site). Only becomes `"/<repo>"` if ever published from a differently named repo. Also exposed as `NEXT_PUBLIC_BASE_PATH`.
- `trailingSlash: true` → routes become `<route>/index.html`.
- `images.unoptimized: true` → GitHub Pages has no image server; `next/image` serves the file as-is. **Photos must be pre-compressed** (see §6.4).
- `turbopack.rules` for `*.css` → left from the create-next-app scaffold; harmless.
- No `redirects`, no route handlers, no Proxy/middleware, no `cacheComponents` (all removed for static export).

### Image paths and basePath
`next/image` does **not** add basePath to `src` in static export. `src/lib/assets.ts` prefixes `NEXT_PUBLIC_BASE_PATH` onto every resolved image path. Always render images through `resolveMedia()` / `resolveGallery()`; never hard-code `/images/...` in a component.

### Asset manifest (how images "appear automatically")
`scripts/generate-asset-manifest.mjs` runs automatically before `npm run dev` and `npm run build` (`predev` / `prebuild`), or manually with `npm run assets`. It lists every image under `public/images` into `src/data/generated/asset-manifest.json`. Data files reference images **without** needing the extension (`/images/profile/portrait` matches `.jpg/.jpeg/.png/.webp/.avif`). If a file doesn't exist, the image (or section) simply isn't rendered — **the site never shows placeholder boxes**.
In `npm run dev`, restart the server (or run `npm run assets`) after adding images.

### SEO
- `layout.tsx` metadata: title `Mubarak Al-Qahtani`, description, Open Graph (`type: profile`), Twitter card, canonical `/`, `metadataBase` from `NEXT_PUBLIC_SITE_URL` (set by CI to `https://mubqhtani.github.io`; falls back to `http://localhost:3000` locally).
- `page.tsx` embeds JSON-LD (schema.org `Person`) generated from the data files.
- `robots.txt` allows all; `sitemap.xml` lists the home page.

## 5. Design system

### Direction
Light, calm, welcoming, content-first. *"Simple but not boring, minimal but not empty, professional without feeling corporate."* Real photos carry the visual interest; the UI stays quiet. One accent color, no decorative effects.

### Colors (`src/app/globals.css` → `@theme`)
Tailwind v4 turns each `--color-*` token into utilities (`bg-bg`, `text-muted`, `ring-line`, …).

| Token | Value | Used for |
|---|---|---|
| `--color-bg` | `#f5f7fb` | Page background (cool off-white, slight blue bias) |
| `--color-surface` | `#ffffff` | Raised surfaces: Highlights card, Black Hat card, skill chips |
| `--color-fg` | `#0e1628` | Main text (deep navy), primary button background |
| `--color-muted` | `#566176` | Secondary text, labels, meta lines |
| `--color-line` | `#e2e6ee` | Hairlines, card rings, timeline rail |
| `--color-accent` | `#2563eb` | Links, badge text, "current" markers, button hover |
| `--color-accent-soft` | `#e9efff` | Badge fill, selection, current-step halo |

Other literal colors (keep in mind when theming):
- Lightbox viewer is always dark: `bg-[#0b1120]/95`, `text-white`, `text-slate-400` (`ui/Lightbox.tsx`).
- Primary buttons use `bg-fg text-white` (`Hero.tsx`, `page.tsx` skip link, `not-found.tsx`); the Black Hat check icons use `text-white` on `bg-accent`.
- Highlights card shadow: `shadow-[…rgb(14_22_40/…)]` in `Hero.tsx`.
- `.link` underline and `.badge-outline` ring use `rgb(37 99 235 / …)` in `globals.css`.
- `layout.tsx` viewport: `themeColor: "#F5F7FB"`, `colorScheme: "light"`; `globals.css` sets `color-scheme: light`.
- `icon.svg` and `opengraph-image.png` have their own fixed colors.

### Typography
| Role | Font | Where |
|---|---|---|
| Display / headings | **Bricolage Grotesque** (`font-display`, var `--font-bricolage`) | Name (h1), section titles, achievement titles, wordmark, mobile menu |
| Body / UI | **Geist** (`font-sans`, default) | Everything else |
| Mono | **Geist Mono** (`font-mono`) | Certificate ID only |

Scale:
- h1 (name): `clamp(2.75rem, 1.9rem + 3.8vw, 4.5rem)`, bold, leading 1.02, tracking −0.035em.
- Section title (`.section-title`): `clamp(1.75rem, 1.35rem + 1.4vw, 2.375rem)`, weight 650, tracking −0.025em.
- Achievement titles: `text-xl md:text-2xl`, semibold. Body: 15–17px, `leading-relaxed`. Meta: 14–15px muted.
- Running text max width `.measure` = 62ch. Headings use `text-wrap: balance`. Numbers use `.tabular`.

### Spacing & layout
- Container `.container-x`: max-width **1080px**, side padding 1.25rem (2rem from 640px).
- Hero: `pt-28 md:pt-36`, `pb-14 md:pb-20`; two columns on `lg` (`1.1fr / 0.9fr`): text left, Highlights card right.
- Sections (`Section.tsx`): each starts with a hairline (`border-t border-line`, container width), `py-14 md:py-20`, heading then content `mt-8 md:mt-10`.
- Header: fixed, 64px; transparent at top, `bg-bg/85 + blur + bottom border` after scrolling.
- Radii: photos & cards `rounded-2xl`, certificate `rounded-xl`, buttons/chips/badges fully round.
- Breakpoints (Tailwind defaults): `sm 640`, `md 768` (desktop nav appears), `lg 1024` (hero goes two-column).

### Components & interaction
- **Badge** (`.badge`): pill, accent-soft fill + accent text = a result (1st, 2nd, PCEP). **`.badge-outline`** (white with accent ring) = in progress (Black Hat "Stage 3"). This filled-vs-outlined difference is intentional state encoding.
- **Photo** (`ui/Lightbox.tsx`): clickable image (`cursor-zoom-in`), slight opacity on hover, opens a full-screen native `<dialog>` showing the **uncropped** image; Esc/backdrop/× closes it.
- **Gallery**: thumbnail row under an entry, only when its folder has images; arrow keys navigate.
- **Navbar**: highlights the section in view (IntersectionObserver); mobile menu (<768px) locks scroll, traps focus, closes on Esc.
- Motion: none except color transitions, the lightbox fade, and smooth anchor scrolling — all disabled under `prefers-reduced-motion`.
- Accessibility: skip link, landmarks, `aria-labelledby` on sections, visible focus ring (2px accent), alt text on every photo.

### 6.4 How to add or change content
- **Text:** edit the matching file in `src/data/`. Achievements/learning/skills render in array order.
- **New achievement:** add an object to `achievements` in `achievements.ts`; put its photo at `public/images/achievements/<id>/cover.jpg`. It appears in both the Highlights card and the Achievements section.
- **Extra photos:** `public/images/achievements/<id>/gallery/01.jpg, 02.jpg …` → thumbnails + viewer appear automatically.
- **Portrait (optional):** `public/images/profile/portrait.jpg` → small round photo above the name.
- **Project:** add to `projects.ts` (+ `public/images/projects/<id>/cover.jpg`, 16:10). The section and nav link appear automatically.
- **Contact:** add `href` (and optional `handle`) to entries in `profile.socials`. Contact section + nav link appear automatically; links also go into JSON-LD.
- **Crop a photo:** add `position: "x% y%"` to its `image`.
- **Photo prep (important — no image optimization on Pages):** strip location metadata; resize to ≤ ~1600px on the long side; JPEG quality ~80–85; aim for ≤ ~200 KB each. Example (run in the project, Node has `sharp`):
  ```bash
  node -e "require('sharp')('in.jpg').rotate().resize({width:1600,height:1600,fit:'inside',withoutEnlargement:true}).jpeg({quality:85,mozjpeg:true}).toFile('public/images/.../cover.jpg')"
  ```
- After adding images in dev: restart `npm run dev` (or `npm run assets`).

## 8. Design decisions and things to avoid

The owner explicitly rejected "AI slop". Keep it that way.

**Decisions (with reasons)**
- Light theme as the published look — an earlier dark version felt "depressing, dull and confusing".
- Summary first: the Highlights card answers *who / what / achieved* within one screen.
- Achievements come right after the hero; every fact appears once (no repeated stat strips or duplicate timelines).
- Real photos are the main visual element; UI chrome stays quiet. One accent color.
- Empty sections are hidden rather than filled with "coming soon" placeholders.
- No numbered section markers (`01 / 02`) — they would be decoration, not information.
- English only (Arabic version and language switcher were removed on request).
- Static export only; no backend — free hosting and nothing to attack or maintain.

**Avoid**
- Glows, neon, heavy gradients, noise/grain, grid backgrounds, glitch/scanline effects, decorative icons or emoji.
- Scroll-triggered reveal animations, parallax, typing effects, cursor effects.
- Many identical cards; stat tiles; skill percentages/progress bars.
- Marketing language ("passionate developer", "turning ideas into reality"), self-praise, filler text.
- Inventing facts, dates, technologies or projects.
- Copying any reference site (azoz.my was a quality reference only — never copy its design, colors, layout, components or text).
- Hard-coding image paths in components (breaks basePath) or adding server features (breaks static export).
